pandas:
Если базовые списки и словари — это единичные кирпичики в памяти, 
то pandas собирает их в полноценные двумерные таблицы. 
В Python такая таблица называется DataFrame

DataFrame — это полный аналог таблицы из PostgreSQL или листа в Excel, 
только живет он прямо в оперативной памяти твоего скрипта


Чтение файлов: CSV, XLSX
pip install openpyxl
В реальности данные отдают в двух форматах: .csv (простой текстовый файл, где колонки разделены запятой или точкой с запятой) и .xlsx (классический Excel).
Библиотека pandas умеет читать их буквально в одну строчку с помощью встроенных магов: read_csv() и read_excel(). 
Они сами открывают файл, понимают, где заголовки, и мгновенно превращают всё это в готовую таблицу (DataFrame) в оперативной памяти.
1. Чтение CSV (sep - это разделитель колонок, обычно ',' или ';')
df_csv = pd.read_csv('my_data.csv', sep=',')

2. Чтение Excel (указываем название файла)
df_excel = pd.read_excel('my_report.xlsx')


psycopg и SQLAlchemy:
pip install sqlalchemy psycopg2-binary
Пока скрипт работает, отфильтрованный DataFrame живет в оперативной памяти, 
но после завершения программы он исчезает. 
В реальной работе аналитику нужно уметь писать скрипты, 
которые забирают грязные файлы, чистят их через pandas и автоматически 
складывают готовую витрину прямо в PostgreSQL для дальнейшей работы в BI-системе.

Для этого используется библиотека SQLAlchemy, которая создает «движок» (engine) 
подключения, и встроенный метод pandas под названием to_sql(), 
который сам генерирует SQL-запросы CREATE TABLE и INSERT INTO под капотом
Шаблон: 'postgresql+psycopg2://пользователь:пароль@сервер:порт/имя_базы'
Локально сервер обычно 'localhost', порт '5432', пользователь 'postgres'

я написал классический ETL-пайплайн (Extract, Transform, Load): 
скрипт извлек данные из внешнего файла, трансформировал (очистил) их в оперативной памяти и загрузил в хранилище. 
Именно так работают дата-инженеры на реальных проектах


ОЧИСТКА ДАННЫХ
Когда ты загружаешь реальный CSV-файл, в нем обязательно будут проблемы, 
которые сломают базу данных. У pandas есть арсенал для их устранения:

Дубликаты: Задвоенные строки появляются из-за сбоев во внешних системах. 
Убираются одним вызовом метода .drop_duplicates().

Битые типы данных: Кто-то мог написать слово "бесплатно" в колонке с ценами. 
Функция pd.to_numeric(..., errors='coerce') жестко переводит колонку в числа, а
любой текст, который не смогла перевести, превращает в специальное значение 
пустоты — NaN (Not a Number).
Когда ты добавляешь errors='coerce' (от англ. coerce — принуждать), 
ты даешь команде четкую инструкцию:
«Попытайся перевести весь столбец в числа. А если встретишь неадекватный текст, 
не роняй программу, а просто принудительно преврати эту ячейку в 
системную пустоту — NaN (Not a Number)».

Пропуски (NaN / None): Пустые ячейки не дают считать агрегаты. Их можно либо 
заполнить нулем через .fillna(0), 
либо полностью удалить строку с помощью .dropna().


АНАЛИТИКА в пайтон
Мы уже умеем делать JOIN и GROUP BY на уровне базы данных. Но дата-инженеру часто
нужно объединять таблицы и агрегировать данные прямо в оперативной памяти 
Python, до загрузки в базу.

Теория: Аналоги SQL в Python
Склейка таблиц (.merge()): Работает точно как JOIN. Ты указываешь левую таблицу, 
правую таблицу, ключ соединения (on) и тип соединения 
(how='inner', how='left').

Группировка (.groupby()): Аналог GROUP BY. Сначала ты указываешь, по какой колонке
бьем на группы, затем — к какой колонке применяем математику, и 
в конце саму функцию (.sum(), .count(), .mean()). Метод .reset_index() 
в конце нужен просто для того, чтобы итоговый результат остался красивой 
плоской таблицей.


ФАСОВАНИЕ ГРЯЗНЫХ ДАННЫХ
До этого мы просто выметали строки с ошибками в мусорку с помощью .dropna(). 
В реальной инженерии мы должны разделить данные на два независимых потока: 
чистые — в базу, грязные — в файл-карантин.

Поиск пустот (.isna()): Метод проверяет ячейки и возвращает True, если там 
системная пустота (NaN или None). Идеально для отлова битых строк.

Поиск заполненных ячеек (.notna()): Делает обратное — оставляет строки, 
где есть валидные данные.

Экспорт из pandas (.to_csv()): Чтобы выгрузить DataFrame из оперативной памяти 
обратно на жесткий диск в виде файла, используется метод 
.to_csv('имя_файла.csv', index=False).


ТЕОРИЯ: Переименование колонок (.rename()): Часто из внешних систем приходят данные с ужасными названиями столбцов (например, "Имя клиента", "Возраст"). 
В базу данных такие названия с пробелами и кириллицей класть нельзя — нужно переименовать их в нормальный змеиный регистр (snake_case), например, "client_name", "age". 
Для этого в pandas используют метод .rename(columns={"старое_имя": "новое_имя"}).

Заполнение пустот (.fillna()): В прошлый раз мы удаляли пустые строки через .dropna(). Но если у клиента не указана скидка, это не значит, что чек нужно удалять. 
Это значит, что скидка равна нулю. Метод .fillna(0) безопасно заменит все NaN в колонке на ноль.

Чтение JSON (pd.read_json()): Формат JSON (JavaScript Object Notation) — это стандарт обмена данными в вебе. Выглядит он как массив словарей. Pandas читает его так же легко, 
как CSV, одной командой.


ЧТЕНИЕ БД и ФУНКЦИЯ КОНВЕЙЕР
Чтение из БД (pd.read_sql()): Вместо read_csv, pandas умеет напрямую отправлять SQL-запросы в твою базу. Ты передаешь ему строчку с SQL-запросом и свой engine 
(мост SQLAlchemy). Библиотека сама стучится в базу, выполняет запрос и моментально превращает результат в красивый DataFrame в оперативной памяти Python.

Архитектурная упаковка (def + try/except): На реальном сервере скрипты работают 24/7. База данных может временно отвалиться (перезагрузка, пропал интернет). 
Если скрипт написан «простыней», он упадет с красной ошибкой. Чтобы этого не было, 
весь логический блок работы с БД оборачивают в функцию и защищают общим блоком try/except Exception as e:.
